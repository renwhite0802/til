# [タイトル：VPCフローログを用いた調査方法、勘所]

- 日付: 2026-06-02

## 背景 (Context)
- オンプレミスからVPN経由でプライベートサブネットのEC2インスタンスへのRDP接続が失敗している
- ネットワークトラフィックがブロックされている箇所を特定し、効果的なトラブルシューティングを行う

## 躓いたポイント (Problem)
- VPN接続経由でオンプレミスユーザーとの間のリモートデスクトッププロトコル（RDP）トラフィックを許可するルールがあります。オンプレミスユーザーはEC2インスタンスに接続できず、タイムアウトエラーを受信する

## 解決策 (Solution)
- EC2インスタンスのElastic Network Interface用のVPC Flow Logsを作成して、拒否されたトラフィックを確認する
- VPCフローログで送信元IP、送信先IP、ポート、プロトコル、ACCEPTまたはREJECTのアクションを記録しているため、ネットワーク接続のトラブルシューティングとして最適
- Amazon Cloudwatch Logsでは、ネットワークトラフィックのフロー情報を直接キャプチャする機能がないため今回の例だと不適切

## 教訓 (Takeaway)
- ネットワーク接続エラーにおいて何が原因化を考えると、
　- セキュリティグループの設定漏れ
　- NACLによるブロック
　- ルートテーブルの問題
　- VPN接続の問題
があるため、トラフィックが実際に到達しているか、どこでブロックされているかを確認する
VPC フローログを使えばENIを出入りするネットワーク接続と、そのステータスが確認できる。もしトラフィックがrejectされていたらセキュリティグループやNACLの設定漏れの可能性が高い
- CloudWatch LogsはアプリケーションレベルのログやOSレベルのイベントログを収集しますが、ネットワークパケットレベルのトラフィックフロー情報は提供しない
