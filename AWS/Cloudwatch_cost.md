# CloudWatchにかかる料金について

## 背景 (Context)

- 業務利用しているCloudWatchの料金を抑える方法を確認する

## 躓いたポイント (Problem)

- なし（ただし、カスタムメトリクスとアラームの料金単価が混同しやすいため整理が必要）

## 解決策 (Solution)

AWS公式の料金体系に基づき、混同しやすい項目を正しく整理。Lambda等でディメンションを動的に生成している場合、カスタムメトリクスが大量に作られて課金対象になるケースがある。

- 無料枠（CloudWatch Free Tier）の範囲
  - カスタムメトリクス：10個まで無料
  - アラーム：10個まで無料（標準解像度）
  - ダッシュボード：3つまで無料（最大50ウィジェット）

- 無料枠を超過した場合の料金（主要リージョン）
  - カスタムメトリクス（11個目以降）：$0.30/月（1メトリクスあたり）
  - アラーム（11個目以降）：$0.10/月（1アラームあたり）
  - ダッシュボード（4個目以降）：$3.00/月（1ダッシュボードあたり）

```bash
# 現在作成されているメトリクスの一覧を確認する
aws cloudwatch list-metrics

# 設定されているアラームの一覧を確認する
aws cloudwatch describe-alarms
```

参考URL: https://aws.amazon.com/jp/cloudwatch/pricing/
参考URL: https://zenn.dev/yuyan/books/a5123767533393/viewer/5bfd3f

## 教訓 (Takeaway)

- 不要なカスタムメトリクスやアラームは作成せず、無料枠である各10個までに抑える
- Lambdaなどで動的にディメンション（ユーザーIDや高頻度で変わる値など）を付与してPutMetricDataを呼び出すと、カスタムメトリクスが爆発的に増えて課金されるため設計段階で抑止する
